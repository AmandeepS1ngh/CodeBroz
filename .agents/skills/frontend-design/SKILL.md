# Frontend Design

Design interfaces that feel intentionally crafted rather than AI-generated. Every visual decision should reinforce the product's identity, audience, and purpose.

Think like a senior product designer responsible for both aesthetics and usability. Prioritize clarity, consistency, accessibility, and memorable design over visual decoration.

---

# When to use this skill

Use this skill when the task involves:

- Designing a new website
- Creating landing pages
- Designing dashboards
- Building admin panels
- Creating login or authentication screens
- Building SaaS interfaces
- Designing portfolios
- Creating responsive web applications
- Improving existing UI
- Creating design systems
- Choosing typography
- Creating colour palettes
- Improving visual hierarchy
- Building reusable UI components
- Improving accessibility
- Modernizing legacy interfaces

Do NOT use this skill for backend development, API implementation, or database architecture.

# Design Workflow

Always follow this order.

## Step 1 — Understand the Project

Before designing, identify:

- What is being built?
- Who is the target audience?
- What problem does it solve?
- What is the primary action users should take?
- What emotions should the interface create?

If the brief doesn't provide enough information, infer reasonable assumptions based on the project.

---

## Step 2 — Define the Visual Direction

Before writing any code, establish a design language.

Create:

- Primary colour
- Secondary colour
- Accent colour
- Neutral colours
- Typography pair
- Border radius system
- Shadow system
- Spacing scale
- Icon style
- Button style
- Card style

Every component should follow the same design language.

---

## Step 3 — Build a Design System

Choose consistent values for:

### Colours

Create a palette containing:

- Primary
- Secondary
- Accent
- Background
- Surface
- Text Primary
- Text Secondary
- Border
- Success
- Warning
- Error

Avoid random colours throughout the interface.

---

### Typography

Use a clear hierarchy.

Example:

- Display
- Heading 1
- Heading 2
- Heading 3
- Body
- Caption
- Button

Limit the design to one display font and one body font.

Typography should communicate personality.

---

### Spacing

Use a consistent spacing scale.

Example

4px

8px

12px

16px

24px

32px

48px

64px

96px

Avoid random spacing.

---

### Border Radius

Choose one radius system.

Example

Small

Medium

Large

Extra Large

Use consistently across components.

---

### Shadows

Create only a few elevation levels.

For example

Level 1

Level 2

Level 3

Do not give every element a different shadow.

# Design Principles

## Design for the User

Every element must help the user complete a task.

Remove decorative elements that don't improve understanding.

---

## Strong Visual Hierarchy

Users should immediately know:

- what is important
- what is secondary
- what is clickable
- what requires attention

Use size, colour, spacing, and contrast.

Avoid relying solely on colour.

---

## Consistency

Buttons should look consistent.

Cards should look consistent.

Spacing should be consistent.

Typography should be consistent.

Icons should follow one style.

The interface should feel like one product.

---

## Simplicity

Every page should have one clear purpose.

Avoid unnecessary animations.

Avoid excessive gradients.

Avoid visual clutter.

---

## Accessibility

Always ensure:

- sufficient colour contrast
- keyboard accessibility
- visible focus states
- semantic HTML
- readable font sizes
- descriptive labels
- responsive layouts

Never sacrifice usability for aesthetics.

---

## Responsive Design

Design mobile first.

Support:

Mobile

Tablet

Laptop

Desktop

Large Desktop

Layouts should adapt naturally.

Avoid horizontal scrolling.

# Common Mistakes to Avoid

Do not:

- Use random colours
- Mix multiple design styles
- Add unnecessary gradients
- Overuse shadows
- Use inconsistent spacing
- Ignore accessibility
- Ignore responsiveness
- Create generic hero sections
- Copy common AI-generated layouts
- Use placeholder text when meaningful content can be written
- Add animations everywhere
- Overcomplicate simple interfaces
